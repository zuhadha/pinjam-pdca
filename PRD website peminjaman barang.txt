# 📘 **PRODUCT REQUIREMENTS DOCUMENT (PRD)**

## **Aplikasi Peminjaman Barang Internal Kantor**

**Versi:** Final
**Target User:** ±200 internal staff
**Platform:** Web App
**Stack Final:**

* **Frontend:** Next.js 15 (App Router), Tailwind CSS, shadcn/ui
* **Backend:** Supabase (Auth + Database + Storage + Edge Functions)
* **DB:** Supabase PostgreSQL
* **Storage:** Supabase Storage
* **Deployment:** Vercel

---

# 1. **OBJECTIVE**

Membangun aplikasi internal yang memudahkan karyawan untuk:

* Melihat katalog barang kantor
* Melakukan peminjaman barang
* Admin mengelola barang & memonitor peminjaman
* Menampilkan dashboard analitik penggunaan barang

Sistem harus **responsif, mudah digunakan, aman**, dan cukup **scalable untuk 200 pengguna**.

---

# 2. **USER ROLES**

## **1. Guest (tanpa login)**

* Akses landing page
* Melihat katalog snippet di landing page
* Membuka halaman katalog barang
* Melihat status barang (tersedia / tidak)
* Mengklik “Pinjam Barang” → diarahkan ke login

## **2. User (logged-in employee)**
* Mengakses katalog lengkap
* Melihat detail barang
* Mengirim permohonan peminjaman barang
* Melihat status permohonan
* Mengembalikan barang (via button return)

## **3. Admin**
* Semua fitur user
* CRUD katalog barang
* Melihat dashboard analitik
* Melihat semua riwayat peminjaman
* Mengapprove / menolak permohonan peminjaman
* Melihat barang yang overdue
* Melihat statistik dan grafik penggunaan

---

# 3. **HALAMAN UTAMA**
# **3.1 Landing Page**
**Tujuan:** memberikan informasi dasar sebelum user login.
### **Sections**
#### A. Hero Section
* Judul
* Subjudul
* CTA: “Lihat Barang Tersedia”

#### B. Rules Peminjaman
* Daftar aturan peminjaman barang (fix, static content)
* Format bullet points

#### C. Snippet Katalog Barang
* Menampilkan **4–6 barang** acak atau populer
* Informasi: nama barang, kategori, status ketersediaan, foto
* Tombol **“Pinjam Barang”**

  * Jika belum login = redirect login
  * Jika login = buka form peminjaman

#### D. QnA Section
* FAQ sederhana (accordion)

### **Akses**
* Bisa diakses semua user, tanpa login

---

# **3.2 Halaman Katalog Barang**

## **Features:**

* Search bar (search by name, category)
* Filter kategori
* Filter status (available / borrowed)
* Daftar barang dalam bentuk card grid
* Card menampilkan:

  * Foto
  * Nama
  * Kategori
  * Jumlah unit tersedia
  * Status: Available, Borrowed, Maintenance
  * Button “Pinjam”

### **Flow ketika user klik “Pinjam”:**

* Jika belum login → redirect login
* Jika login → tampilkan form peminjaman (modal)

  * tanggal pinjam
  * tanggal kembali
  * keperluan
  * catatan tambahan

---

# **3.3 Halaman Kelola Barang (Admin Only)**

### **Akses:**

* Hanya admin
* Berbasis **layout dashboard** dengan sidebar

### Isi:

## A. Dashboard Overview

* Total barang
* Total kategori
* Barang dalam keadaan dipinjam
* Barang rusak/maintenance
* Shortcut ke Kelola Barang dan Riwayat Peminjaman

## B. Menu Kelola Barang (CRUD)

### **Fitur:**

* Melihat list barang (table)
* CRUD lengkap:

  * Create Barang
  * Edit Barang
  * Upload foto barang (Supabase Storage)
  * Soft delete barang (`is_active = false`)
* Field barang:

  * id
  * nama
  * deskripsi
  * kategori
  * stok_total
  * stok_available
  * lokasi penyimpanan
  * foto_url
  * status default = available

# **3.4 Dashboard Analitik (Admin)**

## **Tujuan:** memberikan insight penggunaan aset kantor.

### **Grafik & Data:**

1. **Barang paling sering dipinjam** (bar chart)
2. **Jumlah peminjaman per bulan** (line chart)
3. **Kategori barang yang paling diminati**
4. **Barang yang sering overdue**
5. **Persentase ketersediaan barang**

### **Halaman Tambahan Admin**

* **Daftar pengajuan peminjaman**

* **Daftar barang sedang dipinjam**

  * status overdue
* **Riwayat peminjaman barang**

# 4. **FITUR INTI APLIKASI**

## **4.1 Peminjaman Barang**

### Flow:

1. User memilih barang
2. Input form:

   * tanggal pinjam
   * tanggal kembali
   * keperluan
   * catatan
3. Sistem memvalidasi:

   * stok available > 0
4. Admin menerima request
5. Admin approve / reject
6. Jika approve:

   * stok_available -= 1
7. Setelah user mengembalikan:

   * stok_available += 1
   * admin verifikasi pengembalian

## **4.2 Status barang:**

* Available
* Borrowed
* Maintenance
* Lost
* Inactive

# 6. **NON-FUNCTIONAL REQUIREMENT**

## **Security**

* Auth by Supabase Auth
* RBAC via Supabase policies
* Admin protected routes with RLS
* Prevent double booking via DB constraint
* File upload validated (only jpg/png)

## **Performance**

* Query katalog ≤ 150 ms
* Dashboard analytics ≤ 200 ms
* Image CDN via Supabase

## **Scalability**

* 200 pengguna aktif
* up to 5K borrow_logs per tahun
* index search di name & category
